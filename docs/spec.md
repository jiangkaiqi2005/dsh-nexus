# Nexus 首版 Spec

状态：设计已确认，尚未实现。用户于 2026-10-08 确认本设计准确表达其目标，并要求本轮只完成前置工作与 Spec，不编写插件或技术探针代码。

项目与包名：`dsh-nexus`。面向用户的名称：Nexus。发布状态：本地文档；尚未配置独立项目 Issue tracker，未创建 Issue 或实际添加标签。配置后按 `to-spec` 使用 `ready-for-agent` 标签发布。

## 问题陈述

用户希望通过持续实时交流，让一个管家理解目标、安排 agent 工作、观察结果并继续推进。现有会话需要用户自己选择、发指令、等待与搬运结果；给单个工作会话加语音输入输出，仍不能统一管理已有会话。

用户需要一个独立的 DeepSeek Harness 插件：唯一主管直接使用 Realtime 模型听、说、理解和调度，将 Harness 会话视为可调度的工作对象。耗时任务执行期间，用户仍能通话、改变要求，或挂断后让工作继续。

## 解决方案

Harness 原生侧栏提供固定 Nexus 入口，进入独立主会话。Nexus 与用户实时通话，默认负责理解、拆解、调度和检查结果，具体工作交给 Harness 工作会话。它能访问与操作全部已有和新建工作会话，工作结果自动回到主会话中的主管。

用户的明确指令优先。用户改变要求时，通过原生运行中引导进入相关上下文，由 Nexus 和工作 agent 自行调整后续行动。追加修复、安排审查、结束任务、报告阻塞及是否、何时汇报都由 Nexus 根据目标和实际结果判断。

挂断结束语音交流，主管与工作会话继续运行。同一个 Realtime 型号在同一个主会话中处理文字和工具，停止音频生成与播放。会话保存、恢复及 Harness 退出重启后的行为沿用原生机制。

提供默认关闭的“启动 Harness 后自动进入 Nexus 语音”选项。开启后，每次 Harness 进程启动自动尝试接通一次；主动挂断、页面刷新和切换会话不会重新开麦，用户可以手动再次接通。

## 实现决定

### 主管与工作会话

- 只有一个 Nexus 主管。首版型号沿用 `qwen3.8-omni-flash-realtime`，通过 DashScope Realtime WebSocket 直接处理文字与语音。
- Host 承载主管模型连接、消息处理和工具执行；客户端负责音频采集、播放及原生界面入口。主管生命周期独立于通话与页面生命周期。
- 工作会话继续使用 Harness 原生 agent、上下文与界面。默认将具体执行委派给工作会话是职责分工，不是 Nexus 的能力限制。
- Nexus 不设额外会话权限、归属交接、工具白名单或人工审批。接入原生工具执行与授权配置，实现用户选定的完整能力；首次系统麦克风许可仍由平台正常处理。
- 主管提示词与工具按 Nexus 职责设计。复用现有适配的已验证协议经验，不引入 Qiyu 的人格或记忆业务机制。

### 原生接入与消息记录

- 自定义 Realtime Agent 注册到原生 agent registry、绑定原生主会话，是当前候选接入路线；保留默认 AgentLoop 创建和执行工作会话。
- 不替换全局唯一 agent factory，不假设普通单请求模型适配器天然支持持续双工输入。候选 driver 的完整兼容性尚未实测。
- 主管消息、工具调用和结果必须进入原生事件与持久化生命周期，正确关联 turn、step 和消息身份。创建内存 Session 或在界面显示文字不构成持久化验收。
- 恢复采用 Harness 原生持久化与中断语义，不另建主管会话数据库，也不增加重启后自动续跑机制。
- 保留默认工作会话工厂时，不能假定通用 resume 会自动恢复为 Realtime 主管。插件必须识别主管会话身份，用原生持久化恢复其记录，并登记对应的 Realtime driver；不能将主管恢复为默认工作 agent。恢复入口的完整兼容性列入首阶段验证。
- 如插件扩展点不能满足独立主管与原生持久化，需要先明确接口缺口；不能将需求静默改成双主管、改宿主核心或独立存储产品。

### 全局调度、观察与来源

- 原生父子 subagent 通信不足以覆盖全部已有会话。会话桥接必须覆盖全局目录、读取、创建、投递、运行中引导、原生停止操作及结果订阅。
- Nexus 可观察全部工作会话，自动回流轮次完成、失败和中断等终态及最终结果。读取细节使用原生会话能力，不无限复制所有 token 和日志到主管上下文。
- 结果携带会话身份、相关消息或轮次身份、终态和实际结果内容。投递可去重，并排除主管自身输出，防止反馈循环。
- 主管忙时保留待处理结果，在后续模型处理机会接收；闲时唤醒同一个主管。订阅到事件、消息入队和模型已处理是不同状态。
- 用户输入、Nexus 调度和自动工作结果保留可辨识来源。派活在原生层面是用户消息，记录中标明经由 Nexus；工作会话中真实用户的直接引导同步给 Nexus，派活不回流（ADR 0004）。
- 用户明确指令优先，通过上下文、来源和原生 steer 表达。工作 agent 在后续步骤自行理解和调整；不加入指令版本仲裁、额外意图分类或收到新指令就自动强制取消。
- 原生引导不保证撤销已完成动作，也不保证瞬时打断正在执行的工具。主管可根据用户要求选择原生停止能力，但不在 Host 写死该决定。
- 派活、工作区选择、并发修改协调、追加修复、审查、结束与汇报由 Nexus 判断，不设置固定循环、迭代次数或完成必播报规则。
- 用户裁定（2026-10-09）：Nexus 只管理、调度对话会话（普通会话）的 agent；会话 agent 产生的 subagent 会话 Nexus 不管。

### 音频与启动

- 通话采用模型原生语音能力与正常轮次、打断机制。工作会话执行与用户交流可并行。
- 挂断停止采集、播放及后续音频生成，处理在途音频响应，转入同型号 text-only 文字与工具模式。只静音播放器不能满足要求。
- 手动再接通延续本地主会话上下文。模型连接可重建，同一型号不意味着永久保留同一个云端 session。
- 服务断线恢复必须区分仍在通话的网络恢复与用户已挂断、页面刷新后的文字状态；后两者不自动重新打开麦克风。
- 自动语音选项默认关闭，保存采用 Harness 原生设置能力。开启后每个 Harness 进程启动周期只自动尝试一次，待 Host 与音频客户端就绪后发起。
- 自动尝试是否已发生由 Host 启动周期状态记录，不能以页面挂载次数判断。多个客户端不得同时采集或播放同一主管的通话音频。
- 设备不可用、系统许可未取得或播放未就绪应显示实际状态；请求发起不等于接通成功。
- Host 仍运行时，关闭语音客户端结束该客户端的音频采集，主管保留文字工作能力。真正退出 Harness 采用原生停止与恢复生命周期。

### 上下文压缩与会话命名

- 主会话复用 Harness 原生压缩：自动与 `/compact` 手动两种入口，摘要、保留近期原文与落盘沿用原生行为；压缩后的新模型连接重放摘要。
- 压缩预算由 Nexus 设定，默认 128k token，可在 Nexus 原生设置修改；不以模型约 1M 的上下文窗口作为触发依据。摘要模型默认沿用普通会话的默认模型，可在 Nexus 设置修改。
- 压缩只发生在主管轮次之间，不打断正在说的话或执行中的工具；通话中在轮次边界重建 Realtime 上下文。
- 主管每轮记录实际 token 用量，使原生用量与上下文压力有真实数据。文字模式每轮重建连接并全量重放的费用，待实测用量后另议。
- Nexus 新建的会话沿用原生自动命名；已有会话被派活不改标题；旧的未命名会话不补。主会话固定名为 Nexus，用户手动改名后不覆盖。

### 兼容基线与实现顺序

- 前置源码核查基线是官方提交 `5badb15009ae1756c3afe0ae0cef1faafc290ccc`，仓库标称版本 `0.2.1-alpha.1`。这是接口研究基线，不是已验证兼容声明；不得把另一发行版与该基线的类型混用。
- 官方支持的应用启动方式是 `dsh` profile；未来集成验证使用真实 Host 加载插件，不将临时拼装的核心 runtime 当成产品入口。
- 相关 npm 包需逐包锁定准确版本，不能依赖不一致的 latest 标签；同名发布版本也不证明与源码核查提交字节一致。
- 后续实现先验证唯一主管原生接入及持久化、已有普通会话控制与结果回流、text-only 工具闭环、用户途中引导四条链路，成功后再展开完整语音界面与调度产品。
- 当前型号的官方 text-only 与 Function Calling 支持已核查，联合链路、模态切换、连接恢复和异步注入仍需实测。旧适配与最新文档存在端点及 schema 差异，先确定实际可用接入配置。
- 本轮不安装或启动 Harness，不调用模型，不编写探针或产品实现。上述验证顺序是后续工程工作的输入。

## 测试决定

### 测试边界与证据

优先使用一个最高层边界：真实 Harness Host 加载 Nexus 插件，从 Nexus 主会话入口操作，观察原生会话记录、工作会话、模型输出和客户端媒体状态。四条关键链路已在设计确认中明确；不为内部函数或类拆出同等数量的验收边界。

测试外部行为和用户目标，不测试函数调用顺序、内部类名或与实现镜像的细节。核心状态包括可见消息、真实模型接收与续答、任务终态、落盘恢复、音频是否生成及播放。单靠模拟模型、静态文档、入队事件或截图不能证明端到端链路成立。

协议顺序、忙时结果排队、去重、模态切换与连接恢复等无法稳定在每次真实调用中制造的情况，可以在同一边界补充可控输入和录制协议验证；记录模拟与真实调用的不同证据，不把模拟结论升级为实机通过。

需要验证的模块是主管运行、原生会话桥接与持久化、结果投递、客户端媒体和启动生命周期。本项目没有现成测试；参考已核查的上游 Agent 自定义登记测试、Session 活跃写句柄测试、AgentLoop 恢复中断测试，以及 SessionController 重连快照与实时事件交接测试。用户引导也需遵守原生 inbox 契约。上游先例的固定提交引用见前置核查报告。现有 Qiyu Realtime 适配可提供已验证事件经验，其通过情况不代表 Nexus 通过。

### 必须覆盖的行为

| 验收项 | 操作与通过条件 |
| --- | --- |
| 唯一主管 | 实时模型完成理解、调度与汇报；没有第二个原生模型主管负责解释用户目标 |
| 原生主会话 | 用户、主管及工具记录进入原生会话；关闭重启后记录可恢复，中断状态遵循原生语义 |
| 既有普通会话 | 使用一个非 Nexus 创建、非其直属子会话的既有工作会话；可读取、发任务及接收结果 |
| 空闲结果 | 主管闲置时工作会话结束；结果唤醒主管并可形成有依据的后续动作 |
| 忙时结果 | 用户正在交流时工作会话结束；结果随后被主管处理，不丢失当前用户输入 |
| 来源与用户引导 | Nexus 派活后用户直接改变工作会话要求；记录与回流可区分来源，派活不回流为用户引导，工作 agent 后续行为及主管安排反映新要求 |
| 正常通话与打断 | 工作期间继续实时交流；用户可打断当前语音回复，正常进入下一轮 |
| 挂断文字闭环 | 挂断后同型号接收结果、执行工具并续答；主会话出现文字，无后续音频生成或播放 |
| 在途挂断 | 正在生成或播放语音时挂断；播放器立即停止，已排队媒体不再播放，后续推理转入纯文字 |
| 手动再接通 | 保留任务与交流上下文，用户无需重复解释目标 |
| 自动语音默认值 | 新安装默认关闭；开启后 Harness 每次启动只自动尝试一次 |
| 挂断与页面生命周期 | 主动挂断后刷新、切换会话或再次挂载页面均不重开麦；重复客户端不形成多路音频 |
| 客户端关闭 | Host 仍运行但语音页面关闭；主管仍能处理文字结果并记录到主会话 |
| 真实连接失败 | 无设备、系统拒绝授权、播放未就绪或模型断线时状态准确；不显示假接通或假完成 |
| 结果身份 | 重复事件不重复推进任务；不同工作会话结果可区分，主管输出不回流给自己 |
| 主会话压缩 | 主会话超过 Nexus 设置的预算后在轮次之间自动压缩；`/compact` 在主会话可见并成功；压缩后文字与语音续答使用摘要，记录用量 |
| 会话命名 | Nexus 新建并派活的会话由原生自动命名，不再停在“未命名”；主会话名为 Nexus |

### 首版完整验收场景

1. 用户向 Nexus 要求：让一个既有工作会话修复报错，再让另一个工作会话审查。
2. Nexus 能直接操作既有修复会话并安排审查；用户在执行期间继续语音交流。
3. 用户途中修改要求；原生引导进入相关会话，工作 agent 与主管按新要求调整后续安排。
4. 用户挂断；工作与主管继续，主会话纯文字处理结果和工具调用。
5. Nexus 根据实际结果自行决定是否追加修复或审查，最终报告修改与验证情况；不要求固定修复审查循环。

## 范围之外

- 跨 Codex、Claude Code 或其他产品的 agent 管理。
- 修改 Qiyu 产品，移植其人格、关系或记忆业务。
- 另一个文字主管、短模型意图分类器、固定任务 DAG 或预设修复审查循环。
- Nexus 特有权限、逐会话授权、人工审批、指令版本仲裁或按新输入自动强制取消。
- 操作系统登录后自动启动 Harness，页面刷新后自动开麦。
- 新的会话存储体系、服务端永久 session 承诺、重启后自动续跑任务。
- 本轮插件实现、探针代码、模型付费调用、真实语音或多会话运行验收。
