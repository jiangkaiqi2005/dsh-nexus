# 派活以用户来源发出，以 Nexus 标记区分

票 03 起派活使用独立来源 `nexus-dispatch`，结果 Harness 原生行为把它当作非用户输入：会话不自动命名（Nexus 新建的会话一直“未命名”），界面只显示折叠的执行请求，而工作 agent 的模型本来就看不到来源字段。2026-10-10 用户裁定派活在原生层面就是用户消息：来源为 `user`，另附“经由 Nexus”的标记，原生命名与界面按用户消息处理；结果回流只凭该标记识别派活，不把它当用户直接引导同步回主管。正文不加转述前缀，工作 agent 把派活视为用户要求；Spec 第 25 条相应收窄为记录与回流可区分来源。

**Considered Options**：保留独立来源、由主管在新建时起标题并调用原生重命名（标题被锁定，不再自动命名，界面仍不是用户消息）；完全当作用户输入不留标记（主管自己的派活会被当作用户引导回流给自己）。

**Consequences**：已落盘的旧派活仍是 `nexus-dispatch`，读取与回流需同时识别两种形态；旧的未命名会话不补标题。Host 中依赖用户来源的其他行为（如最近输入时间）也会计入派活。
