# 06：级联模式的生命周期与 Realtime 一致，并完成安装后的完整场景验收

**要构建的行为：** 在级联模式下，以下行为都和 Realtime 模式一致：
- 开启自动语音后，启动时会自动接通；
- 挂断后手动再接通，上下文保持连续；
- 刷新或切换会话时，不会重新打开麦克风；
- 同一时间只有一个客户端占用音频；
- 关闭客户端或断线后，主管继续在 Host 上处理文字；
- 没有设备、未授权或服务出错时，显示的状态准确。

最后打出独立插件包，装进干净的 profile，用真实的 DashScope 识别与合成，加上用户实际在用的 Harness 默认模型，跑通一次完整场景。

**阻塞于：** 01：Nexus 用原生归档清理工作会话；05：级联通话中的插话打断与录音期间暂缓播放。

**状态：** ready-for-agent（2026-10-14 拆票，尚未实施）。

**范围与约束：** 依据 ADR 0002（经 ADR 0005 修订）和 ADR 0005，以及 Spec 中“接通、挂断与生命周期”这一组用户故事。

- 生命周期验证尽量复用 Realtime 模式现有的测试场景，换成在级联模式下跑。
- 打包、安装和冒烟测试沿用首版票 11（`docs/nexus-v1/tickets/11-clean-install-and-full-scenario.md`）的做法。注意：Desktop 打包运行时，对宿主类做 `instanceof` 判断会失败，所以冒烟测试必须用打包产物跑。
- 不对比两种模式的成本或派活成功率（用户已裁定不做）。
- 实机验收由用户亲自操作，验收结果只记录用户的反馈，不得自行宣称通过。

- [ ] 级联模式下自动语音设置生效：开启后，每次启动 Harness 只尝试接通一次；主动挂断后再刷新，不会重新开麦。
- [ ] 挂断后再接通，主管仍保留之前的任务和交流上下文。
- [ ] 不会出现两个客户端同时占用音频；关闭客户端后，主管仍用文字处理工作结果。
- [ ] 在没有麦克风、拒绝授权、无法播放、识别或合成服务不可用时，客户端状态准确，不会显示假的“已接通”。
- [ ] 独立插件包能装进干净的 profile，冒烟测试通过。
- [ ] 用户实机走完以下场景：在级联通话中点按说话，要求派活；Nexus 用结构化工具派活，并朗读确认；用户插话打断一次；挂断后，工作结果以文字回流；用户要求清理会话时，Nexus 使用归档。

**Spec 对照：** 用户故事 33–37，以及其余故事的端到端组合；测试表中的“再接通 / 自动语音 / 生命周期”。
