# 04：级联通话中点按说话，并用千问 3.1 识别

**要构建的行为：** 级联通话接通后，客户端提供“开始录音 / 结束录音”按钮。用户点开始说话，点结束后，Host 把整段录音交给千问 3.1 语音识别，识别出的文字作为用户发言进入主会话，主管照常回复并朗读。客户端显示“录音中”和“识别中”两种状态。识别失败或没识别出内容时，提示“没听清”，不发起这一轮。单次录音满 60 秒时自动结束。

**阻塞于：** 03：级联通话中把主管回复逐句朗读出来。

**状态：** ready-for-agent（2026-10-14 拆票，尚未实施）。

**范围与约束：** 依据 ADR 0005，以及 Spec 中“点按说话与语音识别”“配置”两节。

- 采用整段上传，不做流式识别。识别协议用 TS 在 Host 侧重新实现，可以参考栖语的千问识别网关。
- 识别的端点和型号都可配置，默认值照搬栖语。凭据复用现有的凭据引用。
- 上行通话流新增“开始录音”“结束录音”两种控制帧，音频帧沿用现有格式。
- 本票不做插话打断，也不做录音期间暂缓播放（票 05）。

- [ ] 一次完整的点按录音后，受控识别端点收到 16 kHz 单声道 WAV 和默认型号，鉴权使用 Host 上的凭据。
- [ ] 识别出的文字以原生用户消息进入主会话：主管空闲时由它发起新一轮；主管正在运行时，作为运行中引导交给主管。
- [ ] 识别端点报错或返回空文字时，不写入用户消息、不发起回合，客户端收到“未听清”状态。
- [ ] 录音满 60 秒时，Host 自动按“结束录音”处理。
- [ ] 打开 `NEXUS_REAL_VOICE` 后，有一个用例用合成语音样本连接真实识别端点，跑通一轮“说话、识别、回复”；默认跳过。

**Spec 对照：** 用户故事 12–17、25；“点按说话与语音识别”“配置”两节的实现决定；测试表中的“点按一轮”“识别失败 / 空结果”“录音上限”。
