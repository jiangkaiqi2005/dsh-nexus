# 03：级联通话中把主管回复逐句朗读出来

**要构建的行为：** 级联模式下可以接通通话。通话中，主管的回复会边生成边按句子交给千问 3.1 语音合成，客户端流式播放；第一句在主管还没说完时就开始播。无论这条回复是被用户打字触发、还是被工作结果回流触发，都会朗读。客户端显示“思考中”和“朗读中”两种状态。挂断后立即停止播放，之后由同一个主管只输出文字。合成在中途失败时，只停掉这一条回复的朗读，文字照常保留，通话不断。

**阻塞于：** 02：级联模式下由 Harness 默认模型担任主管。

**状态：** ready-for-agent（2026-10-14 拆票，尚未实施）。

**范围与约束：** 依据 ADR 0005，以及 Spec 中“语音合成与播放”“配置”两节。

- 合成协议用 TS 在 Host 侧重新实现。可以参考栖语的千问 WS 推理合成网关，但运行时不能依赖栖语。
- 合成的端点、型号和音色都可配置，默认值照搬栖语。凭据复用现有的凭据引用，不得发到客户端。
- 通话中使用语音版提示词。
- 本票不做录音和识别（票 04），也不做插话打断和录音期间暂缓播放（票 05）。

- [ ] 级联模式下可以接通，接通后不保持任何常驻的模型连接。
- [ ] 通话中，主管回复按句子切分后送到受控的合成端点：先 `run-task`，每句一个 `continue-task`，最后 `finish-task`。请求使用默认型号和音色，客户端收到 PCM 音频帧。
- [ ] 主管还在输出时，第一句已经送去合成，客户端也已经收到这句的音频。
- [ ] 工作结果回流后主管的口头汇报会被朗读；工具调用本身不朗读。
- [ ] 挂断后立即停止下发音频；之后的结果回流和工具续答只有文字，不再发出任何合成请求。
- [ ] 合成端点中途报错时，这条回复停止朗读，文字完整保留在主会话里，客户端收到合成失败状态，通话保持接通。
- [ ] 下行帧和客户端状态里都不包含凭据。
- [ ] 打开 `NEXUS_REAL_VOICE` 后，有一个用例连接真实合成端点并跑通一条回复的朗读；默认跳过。

**Spec 对照：** 用户故事 17（思考、朗读状态）、20–21、26–31、38–41；“语音合成与播放”“配置”两节的实现决定；测试表中的“首句先播”“合成失败”“挂断”“凭据不出 Host”。
