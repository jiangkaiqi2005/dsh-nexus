# 05：级联通话中的插话打断与录音期间暂缓播放

**要构建的行为：** Nexus 正在朗读时，用户点“开始录音”，播放和合成立即停止，主管会知道用户实际听到了哪几句。已经发出的工具调用照常执行；用户新说的话识别出来后，按原生运行中引导交给主管。录音期间新生成的语音先不播，等录音结束后再按顺序播放。

**阻塞于：** 04：级联通话中点按说话，并用千问 3.1 识别。

**状态：** ready-for-agent（2026-10-14 拆票，尚未实施）。

**范围与约束：** 依据 ADR 0005，以及 Spec 中“点按说话与语音识别”“语音合成与播放”两节。

- “被打断”提示沿用现有 Nexus 语音提示的形式，精度到句子。
- 插话不丢弃已经发出的工具调用，这一点有意和 Realtime 模式不同。
- 不做语音活动检测，也不做自动打断。

- [ ] 朗读时开始录音：客户端立即停止播放并回报已播放的样本数，合成任务被取消；主会话写入一条句子级的“被打断”提示，只列出用户实际听到的句子。
- [ ] 插话时正在执行的派活等工具调用照常完成，结果被记录并交回主管；插话的识别文字作为运行中引导交给主管。
- [ ] 录音期间新生成的语音不下发给客户端；录音结束后按原顺序下发。

**Spec 对照：** 用户故事 18–19、22–25、28；“点按说话与语音识别”“语音合成与播放”两节的实现决定；测试表中的“录音期间不播放”“插话”。
