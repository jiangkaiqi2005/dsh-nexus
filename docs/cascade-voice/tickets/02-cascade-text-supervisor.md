# 02：级联模式下由 Harness 默认模型担任主管

**要构建的行为：** Nexus 设置里新增一个“语音模式”选项，可选级联或 Realtime，默认是级联。选级联时，主管在主会话里的每一步都交给 Harness 当前的默认模型，按当前的推理强度回答；主管通过原生结构化工具调用读取会话和派活，原生记录里写的是实际使用的提供方和型号。用户直接在主会话打字，就能和级联主管来回对话、让它派活、收到工作结果回流；改了 Harness 默认模型后，下一步立即生效。选 Realtime 时，一切行为和现在一样。

**阻塞于：** 无，可以立即开始。不过票 01 也会改主管提示词，两票不要同时实施。

**状态：** 已完成（2026-10-14），标准与规格两轴最终均 approve，无未决评审问题。

**验证记录：** [本票实施、检查与评审](../verification/02-cascade-text-supervisor.md)。

**范围与约束：** 依据 ADR 0005，以及 Spec 中“语音模式”“主管模型请求接缝”“配置”三节。

- 先做预重构：把主管“请求一个模型回复”的那一步抽成**主管模型请求**接缝，并由现有的 Realtime 连接来实现。做完这一步后，所有现有测试必须保持通过，然后才能加级联实现。级联实现走 Harness 原生的 LLM 服务。
- 级联实现发给模型的历史要用原生结构化消息，不能压平成文本；同时要保留逐段监听文字输出的能力，票 03 会靠它把文字送去合成。
- 不新增“主管模型”设置；摘要模型的设置保持不变。
- 本票不做语音。级联模式下用户尝试接通时，要么明确提示“暂不支持”，要么不提供接通入口；语音从票 03 开始交付。

- [x] 新配置的默认语音模式是级联；切到 Realtime 后，现有的 Realtime 测试全部通过，行为不变。
- [x] 级联模式下在主会话打字，主管的请求发给测试注册的默认 LLM 提供方，并带上默认推理强度；回复写进原生记录，记录里的提供方和型号就是实际使用的那一个。
- [x] 级联主管通过原生工具调用读取工作会话并派活；下一步请求里，之前的工具调用和工具结果都以结构化消息出现，而不是压平成文本。
- [x] 工作结果回流会唤醒级联主管，主管能据此继续行动；主管还在运行时，用户输入的内容按原生引导交给主管。
- [x] 修改 Harness 默认模型后，下一步请求就使用新模型。
- [x] 默认模型请求失败时，主会话按现有的失败方式记录，不会悄悄换用其他模型。
- [x] 级联模式下，主会话超过预算时会在两轮之间压缩，压缩后的请求使用摘要。
