## 问题陈述

用户用 Nexus 语音管理工作会话时，现在只能用 Realtime 模式（`qwen3.8-omni-flash-realtime`）。从实际账单看，主会话约 98% 的花费来自上下文：模型每次回复都会把整段上下文重新计一次输入费。Realtime 模型从未命中过缓存。挂断以后的文字轮更贵，因为每一轮都要新建连接、重放全部上下文。音频的输入和输出加起来只占约 1%。

此外，Realtime 模型偶尔会出现“口头答应派活、实际没有调用工具”的情况，而且它的工具历史只能压平成文本重放。用户愿意多等一会儿，以换取更准确的派活和更低的成本。用户也想直接沿用自己已经在 Harness 里配置好、带上下文缓存的文本模型。

另外一个问题：Nexus 没有归档工作会话的能力。有一次用户要求清理会话，Nexus 只好让工作会话去删除自己的数据，结果引发报错。随后 Nexus 又自己用 shell 反复清理，陷入一个 43 步的循环，约占总花费的一半。

## 解决方案

Nexus 新增级联语音模式，和 Realtime 模式并存，默认使用级联模式。在级联模式下：

- **听写**：用户接通后点一次开始录音、再点一次结束录音。整段录音交给千问 3.1 语音识别，识别出的文字直接作为用户发言。
- **思考与调度**：由主管模型负责理解、调度和汇报。主管模型就是 Harness 当前的默认模型和默认推理强度，它通过原生结构化工具调用来派活。
- **朗读**：回复一边生成，一边逐句交给千问 3.1 语音合成，流式播放。
- **挂断后**：同一个主管模型继续处理文字和结果，但不再合成或播放语音。

用户可以在设置里切回 Realtime 模式，下一次接通时生效。两种模式共用同一个主会话和同一份历史。

Nexus 同时新增“归档工作会话”能力，调用 Harness 原生的归档功能（可以撤销），不再借道工作会话或文件系统去删除数据。

## 实现决定

### 语音模式

- Nexus 设置新增“语音模式”选项：级联或 Realtime，默认级联，可在运行时修改，下一次接通时生效。通话进行中不切换。
- Realtime 模式现有的行为、协议和测试保持不变，包括通话中服务端 VAD、打断截断、挂断后按轮新建 text-only 连接，以及压平后的历史重放。
- 两种模式共用同一个主管、同一个主会话和同一份原生记录。主管轮次的驱动、结果回流、用户引导、压缩和恢复都只有一套。

### 主管模型请求接缝

- 现在主管的每一步都通过 Realtime 连接请求一个回复，拿回“文本、工具调用、是否被打断、结束时间、用量”这几项。为此引入一个**主管模型请求**接缝：输入是当前主会话的原生对话面、组装好的系统提示词和工具定义、取消信号；输出保持现有回复的结构不变。
  - Realtime 模式下，这个接缝由现有的 Realtime 连接来实现。
  - 级联模式下，这个接缝由 Harness 原生 LLM 服务来实现。
- 级联模式每一步读取 Harness 当前的默认模型选择（提供方、型号、推理强度），用原生 LLM 服务流式请求。
  - 历史使用原生结构化消息，包括工具调用和工具结果，不再压平成文本。
  - 工具定义直接用原生组装结果。
  - 用量按原生口径记录，包括缓存命中。
- 级联模式下，主管对外显示的提供方和型号，是那一步实际使用的默认模型，而不是固定的 Realtime 型号。
- 文字流要能逐段交给语音层，让第一句尽早送去合成。现有回复对象有“逐段监听文本”的能力，级联实现要保留它。
- 系统提示词沿用现有分法：通话中用语音版（简短、口语化），挂断后用文字版。
- 默认模型不可用、未登录或请求失败时，按现有的失败语义记录到主会话，不改用其他模型。

### 点按说话与语音识别

- 客户端在通话中提供“开始录音 / 结束录音”按钮。录音期间按现在的方式采集 16 kHz、16 位、单声道 PCM，通过现有的通话流上行。上行消息新增“开始录音”“结束录音”两类控制帧；音频帧沿用现有格式。
- 单次录音上限 60 秒，到时 Host 按“结束录音”处理。
- 结束录音后，Host 把整段音频封装成 WAV，按栖语验证过的千问多模态形状上传。
  - 端点默认 `https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`。
  - 型号默认 `qwen-audio-3.1-asr-flash`。
  - 鉴权用 `Bearer` 加上 Nexus 现有的凭据引用。
- 识别出的非空文字作为用户发言，以原生用户消息进入主会话：主管空闲时发起新一轮，主管运行中时按原生运行中引导交付。
- 识别失败或结果为空时，不写入用户消息、不发起回合，只向客户端推送“未听清”的状态。
- 开始录音会立即停止当前播放，Host 停止向客户端发送合成音频。录音期间新生成的语音先缓存，结束录音后再按顺序播放。

### 语音合成与播放

- 每一条需要朗读的回复，对应一个 DashScope WS 推理合成任务：`run-task`，再对每一句发一次 `continue-task`，最后 `finish-task`。
  - 端点默认 `wss://dashscope.aliyuncs.com/api-ws/v1/inference`。
  - 型号默认 `qwen-audio-3.1-tts-flash`。
  - 音色默认 `longanhuan_v3.1`。
  - 输出为 PCM。客户端播放采样率与 Realtime 模式一致，都是 24 kHz。
- 主管模型的文字流出来后，按中文和英文的句末标点（以及换行）切句，每切出一句就交给合成任务。
- 只有通话中的回复才朗读，挂断后的回复不合成。工具调用本身不朗读。
- 客户端停止播放后，会回报已经播放的样本数。Host 据此算出“用户实际听到第几句为止”，并按现有“被打断语音”提示的格式，以 Nexus 语音提示的形式写入主会话，精度到句子。
- 合成中途失败时，取消这个任务，这条回复不再朗读，文字照常保留在主会话，客户端显示合成失败状态。
- 插话或挂断只会停止播放和合成，不取消主管模型已经发出的工具调用，也不丢弃工具调用的结果。

### 配置

- Nexus 设置新增：语音模式；识别端点、识别型号；合成端点、合成型号、合成音色。默认值即上面列出的栖语默认值。识别和合成复用现有的凭据引用设置。
- 现有的 Realtime 端点、超时、自动语音、压缩预算、摘要模型和摘要推理强度等设置，含义保持不变。
- 级联模式不新增“主管模型”设置，主管模型跟随 Harness 的默认模型。

### 归档工作会话

- 主管工具集新增“归档工作会话”工具：输入一个工作会话 ID，调用 Harness 原生的会话归档，并停止该会话正在进行的活动。返回归档结果，失败时照实返回错误。
- 主会话（Nexus 自己）不能被归档。工具的作用范围和其他工作会话工具相同，即 Nexus 能看到的全部工作会话。
- 主管提示词写明两点：清理会话时使用归档工具，不要让工作会话删除自己或其他会话的数据；原生只支持归档，不支持删除，用户要求删除时应该告知这一点。

## 测试决定

### 测试边界

- 沿用项目现有的最高一层边界：在受控的 Harness Host 中加载 Nexus，从 Nexus 的通话流和主会话入口操作，观察原生会话记录、工作会话、客户端下行帧和状态。不为接缝内部的类或函数另设验收边界。
- 级联模式在同一边界上替换外部依赖：
  - 主管模型：由测试注册的 Harness LLM 提供方担任，并设为默认模型。已有先例是压缩测试里的测试摘要模型提供方。
  - 语音识别：由受控的 HTTP 端点担任。
  - 语音合成：由受控的 WS 推理端点担任。已有先例是语音测试里受控的 DashScope WS 端点。
- 好的测试只断言外部行为：主会话里出现了什么记录、客户端收到了什么帧和状态、受控端点收到了什么请求、工作会话实际状态如何。不断言内部调用顺序。
- 真实端点用例沿用现有的环境变量开关，默认跳过。模拟结论不当作实机通过。

### 必须覆盖的行为

| 验收项 | 操作与通过条件 |
| --- | --- |
| 默认级联 | 新配置下接通即为级联模式；切到 Realtime 后下一次接通走 Realtime，现有 Realtime 测试全部保持通过 |
| 跟随默认模型 | 主管请求发给 Harness 默认模型，带默认推理强度；修改默认模型后下一步就用新模型；记录里显示实际的提供方和型号 |
| 结构化工具调用 | 级联主管通过原生工具调用派活，工具结果以结构化形式回到下一步请求，没有压平的文本 |
| 点按一轮 | 开始录音、上传音频、结束录音后，识别端点收到 WAV 和正确的型号；识别文字作为用户消息进入主会话；回复逐句合成，客户端收到 PCM |
| 首句先播 | 主管还在继续输出时，第一句已经送去合成，客户端已经收到音频 |
| 识别失败 / 空结果 | 不写用户消息、不发起回合，客户端收到“未听清”状态 |
| 录音上限 | 超过 60 秒自动按结束录音处理 |
| 录音期间不播放 | 录音期间生成的语音不下发；结束录音后按顺序下发 |
| 插话 | 朗读中开始录音，播放和合成停止；主会话写入句子粒度的“被打断”提示；已发出的工具调用照常执行并记录结果；新发言按运行中引导交付 |
| 合成失败 | 合成端点中途报错后，该条朗读停止，文字完整保留，客户端收到失败状态，通话保持 |
| 挂断 | 立即停止下发音频；后续回合以纯文字由同一个主管模型处理，没有合成请求 |
| 再接通 / 自动语音 / 生命周期 | 再接通后上下文连续；自动语音、刷新不重开麦、只有一个客户端占用音频、客户端关闭后文字工作继续，这些行为与 Realtime 模式一致 |
| 压缩 | 级联模式下超过预算会在轮次之间压缩，压缩后的请求使用摘要 |
| 凭据不出 Host | 下行帧和客户端状态里都不包含凭据 |
| 归档工具 | 归档一个运行中的工作会话后，原生显示它已归档、活动已停止；不能归档主会话；失败时返回错误 |

### 先例

- 语音测试：用受控 WS 端点模拟 DashScope，测试打断、挂断、重连。
- 压缩测试：用测试 LLM 提供方担任摘要模型，并设置默认模型。
- 派活测试：工作会话工具的端到端验证。
- 栖语的千问识别和合成网关测试可以作为协议细节的参考，但它们通过不代表 Nexus 通过。

## 范围之外

- 免提连续通话、浏览器或服务端的语音检测、说完自动判停、检测到人声就自动打断。点按的“开始 / 结束”就是将来接入这些功能的接缝。
- 流式语音识别（边录边识别），以及千问 3.1 之外的识别或合成提供方，例如 OpenAI 兼容接口、豆包、自定义 HTTP。
- 为级联模式单独设置主管模型、为每个会话单独设置语音模式、通话进行中切换模式。
- Realtime 模式本身的任何改动。
- 两种模式在派活成功率或成本上的对比实测。用户裁定不做；以功能可用作为完成标准。
- 主管工具循环的步数上限、重复调用检测、大工具结果截断或分页、用量明细字段的保留。用户裁定这些都保持 Harness 原生行为。
- 删除会话。原生只有归档。
- Harness 的 glob 不支持 `{a,b}` 花括号写法，这是上游问题，Nexus 不做绕过。

## 补充说明

- 成本依据：用户本机主会话中有用量记录的 141 次回复，上下文输入约占 98%，缓存命中为 0；单次失控的工具循环约占 49%。级联模式是靠主管模型的上下文缓存省钱。按官方价格估算，每轮语音的识别加合成费用略高于 Realtime 模型的音频费用，但在总花费中占比很小。
- 栖语里的千问识别和合成协议细节，包括帧形状、结束码和音色约束，都可以作为参考。但栖语那边这两档是按住说话、整段识别的用法，在 Nexus 里要用 TS 重新实现，不依赖栖语运行。
- 首句 3 秒是设计目标，不作为自动化验收的硬阈值。
