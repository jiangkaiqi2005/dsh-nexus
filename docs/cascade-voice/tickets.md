## 为什么这样拆

- 每张票都在同一个测试边界（受控 Host 加通话流和主会话）上交付一段可以演示的行为。
- 02 先只交付文字形态的级联主管，把风险最大的部分先验证掉：主管模型接缝，以及跟随 Harness 默认模型。
- 03 只加“说”：在通话中打字，或者有工作结果回流，就能听到朗读。
- 04 再加“听”：接通后能完整说一轮。
- 05 处理“听”和“说”交叠的时序问题。
- 06 对齐生命周期，并做最终验收。

## 执行 frontier

本轮按 01 → 02 → 03 → 04 顺序完成，标准与规格两轴均最终放行；总修复 1 轮，发生在票 03。02 内部先完成主管请求接缝预重构与原有回归，再添加级联实现。

按用户指令停在 04，不自动开始 05/06。下次继续的 frontier 为 05 → 06：05 的依赖 04 已完成；06 仍等待 05，01 已完成。依赖与验收要求保持不变。

票 03/04 的真实语音 opt-in 用例已添加但默认跳过、未执行实测，清单保持未勾选并说明原因；受控验收和双轴通过不代表付费端点或物理设备验收。票 04 两次原默认并发运行失败、未知 Host 异常根因与完整串行通过分别保留在验证记录及汇总报告，属于已记录的非阻塞验证限制。
