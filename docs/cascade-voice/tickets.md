## 为什么这样拆

- 每张票都在同一个测试边界（受控 Host 加通话流和主会话）上交付一段可以演示的行为。
- 02 先只交付文字形态的级联主管，把风险最大的部分先验证掉：主管模型接缝，以及跟随 Harness 默认模型。
- 03 只加“说”：在通话中打字，或者有工作结果回流，就能听到朗读。
- 04 再加“听”：接通后能完整说一轮。
- 05 处理“听”和“说”交叠的时序问题。
- 06 对齐生命周期，并做最终验收。

## 执行 frontier

先做 01，然后 02。两张都改主管提示词，所以按顺序做，不并行。之后依次是 03、04、05，最后是 06。02 内部也有顺序：先把主管模型请求抽成接缝，确认现有测试全部通过，再加级联实现。
