## 为什么这样拆

每票都有通过原生界面或真实 Host 可验证的行为，不把工作拆成先做底层、再做 API、最后做 UI 的水平工程。当前没有业务代码需要预重构，因此不加无产出的重构或脚手架票。

01 限定为文字轮次与落盘，优先确认最危险的自定义主管接入；02 独立验证恢复身份与上下文，03 独立验证真实工具派活，两者都只依赖 01。04 使用已能执行的工作会话建立真实结果闭环；05 在该闭环上验证用户改要求后执行与汇报发生变化。

06 必须等恢复、派活、结果和用户引导具备证据，满足 Spec 的先验证核心链路、再展开语音要求。07 和 08 都只需要正常通话，可以分别交付；09 依赖挂断后的文字语义，10 依赖同样的模式转换与既有恢复能力。11 验收最终组合与干净安装。

依赖仅列直接阻塞项，已通过其他票传递的依赖不重复列出。未验证的扩展接口若使 01 或 02 不可行，应报告具体缺口并调整计划，不能默默改成双主管或另一存储方案。
