# 13：派活以用户消息发出并自动命名会话

**要构建的行为：** Nexus 派活在工作会话中就是用户消息：界面显示为用户输入，Nexus 新建的会话像普通会话一样先“未命名”再由原生自动命名。记录中标明经由 Nexus，结果回流据此不把派活当作用户直接引导同步回主管。主会话名为 Nexus。

**阻塞于：** 10：断线或关闭客户端后保留主管工作（等其收尾，避免同时改动回流与主管代码）。

**状态：** 已实施，待用户验收（2026-10-10）。受控自动验证见 `docs/verification/13-dispatch-as-user-and-session-titles.md`；Desktop 侧栏中的实际标题与真实命名模型待用户实机验收。

**范围与约束：** 依据 ADR 0004。派活正文不加转述前缀，工作 agent 把它当作用户要求。不由主管起标题、不调用重命名替代原生命名。已有会话被派活不改标题；旧的未命名会话不补。主会话首次创建或标题仅为兜底时改为 Nexus，用户手动改名后不覆盖。已落盘的旧 `nexus-dispatch` 派活仍须正确识别，不回流、不重复投递。

已知事实（2026-10-10 只读核查，实现时复核）：
- 原生命名只接受来源 `user` 的消息；现有派活来源为 `nexus-dispatch`，故 Nexus 新建的会话无任何标题，界面只显示折叠的执行请求或上下文注入。
- Host 的消息来源可扩展，`user` 来源可携带额外字段并完整落盘（Host 自身的 RPC 用户消息即如此）。
- 结果回流当前把所有 `user` 来源视为用户直接引导。
- 主会话当前标题是早期测试消息形成的兜底标题。

- [ ] Nexus 新建会话并派活后，会话先显示“未命名”，随后由原生模型自动命名；派活在界面显示为用户输入。（隔离 Host 与受控命名模型验证通过：派活前无标题，随后原生兜底标题与模型标题；界面显示仅经原生来源与列表投影核对，Desktop 待实机。）
- [ ] 向运行中与闲置的已有会话派活均成功，已有标题不变。（运行中走原生 steer、闲置走 followup，均执行且标题不变；受控验证通过。）
- [ ] 派活不作为用户直接引导回流到主管；用户在同一会话亲自输入仍照常同步。新旧两种派活记录在重启后都不回流、不重复。（四次启动的受控验证与中继单元测试通过。）
- [ ] 主会话名为 Nexus；用户手动改名后重启不被覆盖。（按协调者裁定，标题缺失或来源不是用户改名时均改为 Nexus；首次创建、兜底与模型标题重启改回、手动改名重启保留均受控验证通过，Desktop 自带运行时冒烟加载通过；用户 Desktop 主会话现有标题待实机确认。）
- [ ] 工作 agent 收到的派活正文与 Nexus 发出的一致，无额外前缀。（落盘正文与工作模型收到的用户文本均与工具参数逐字一致。）

**完成证据：** 隔离 Host 中新建与已有会话的派活记录、原生标题事件、回流记录与重启后去重；Desktop 侧栏中实际标题待用户实机验收。

**Spec 对照：** 用户故事 25（修订）、45；“全局调度、观察与来源”及“上下文压缩与会话命名”实现决定；“来源与用户引导”“会话命名”验收项。
