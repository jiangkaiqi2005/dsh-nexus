# 13：派活以用户消息发出并自动命名会话

**要构建的行为：** Nexus 派活在工作会话中就是用户消息：界面显示为用户输入，Nexus 新建的会话像普通会话一样先“未命名”再由原生自动命名。记录中标明经由 Nexus，结果回流据此不把派活当作用户直接引导同步回主管。主会话名为 Nexus。

**阻塞于：** 10：断线或关闭客户端后保留主管工作（等其收尾，避免同时改动回流与主管代码）。

**状态：** 用户验收通过（2026-10-11）。此前通过的新建派活显示、文字输入镜像与主会话改名重启保持通过；用户本次确认跨会话/项目保持语音并可挂断、点名已有会话派活并实际取消后台计时、新建会话执行后生成模型标题三项全部通过。此前双方无声的反馈经用户确认是麦克风未开启，没有因此修改或重新安装插件。本轮修复基点 `7e97bbc`，实施提交 `434f75e`；标准轴与规格轴均 approve、问题为空，评审修复 0 轮；完整套件 102 项，91 passed / 0 failed / 11 skipped，隔离 Desktop 冒烟 1 passed / 0 failed。票 12 较长已有对话及后续操作仍未验。详见 `docs/verification/13-dispatch-as-user-and-session-titles.md` 最新条目。

**范围与约束：** 依据 ADR 0004。派活正文不加转述前缀，工作 agent 把它当作用户要求。不由主管起标题、不调用重命名替代原生命名。已有会话被派活不改标题；旧的未命名会话不补。主会话首次创建或标题不是用户手动所起（无标题、兜底或模型标题）时改为 Nexus，用户手动改名后不覆盖（首轮评审后按 Spec“主会话固定名为 Nexus”由“仅为兜底”放宽）。已落盘的旧 `nexus-dispatch` 派活仍须正确识别，不回流、不重复投递。

本轮修复（2026-10-10）：用户授权不继续人工验收并明确三项都修。仅本进程 `nexus_create_session` 创建的会话、首次派活触发的原生首条提示词命名辅助请求，沿同一路由以至少 4096 token 输出预算运行；更高原预算保留。实际预算记入含会话 ID 的插件 Host 信息日志，原生请求事件仍为调整前参数，不添加或重复会话事件。切换会话、项目或空白视图保留同一通话，全局原生控件可挂断；关闭客户端与插件仍释放音频。主管派给已有命名会话前先查最新列表；停止业务任务经 worker 原生 job 工具取消并核实，`stop_session` 只停止 agent 当前轮次，接受不代表任务停止完成。主管不起标题、不 `rename` 工作会话；普通、已有和旧会话及工作模型配置不变。此授权取代历史“命名问题不改插件”，ADR 0004 的来源、正文与原生命名规则不变。票 12 未验项不记通过。详见验收记录本轮条目。
