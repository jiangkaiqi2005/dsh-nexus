# 01：从原生侧栏与唯一 Realtime 主管文字交流

**要构建的行为：** 用户在真实 Harness 中安装本地 Nexus bundle，从固定侧栏入口进入主会话，与唯一 Realtime 主管进行文字交流；交流进入原生会话记录。这是第一个可演示的完整切片，同时核实自定义主管接入是否可行。

**阻塞于：** 无，可首先开始。

**状态：** draft，待确认拆分方案；本轮不执行。

**范围与约束：** 按已固定的官方接口基线加载插件，逐包固定准确版本；使用 `qwen3.8-omni-flash-realtime`。仅将语音能力延后，不能增加第二个文字主管。无需改宿主核心、另建会话存储或替换默认工作会话工厂。

- [ ] 通过官方支持的 profile 加载本地插件，入口可见，重复进入指向同一个主会话而非创建多个主管。
- [ ] 在原生界面输入文字，准确型号通过实际 Realtime 连接产生回复；模型配置与凭据沿用 Host 服务，客户端不接收明文密钥。
- [ ] Nexus 自定义 Agent 身份与主会话身份一致，用户消息、主管文字与轮次状态符合原生事件及界面投影契约。
- [ ] 交流记录进入原生持久化；关闭写句柄后可读取完整用户与主管记录，不能以界面显示替代落盘证据。
- [ ] 默认工作会话仍能正常使用自己的原生 agent；主管不是向其 handoff 用户目标的语音壳。
- [ ] 未配置凭据、建连失败、超时或响应失败显示实际状态，不记录假完成；精确记录本次验证的 Host、包版本和模型配置。
- [ ] 在真实 Host 边界演示完整文字轮次，并补充必要的失败及身份释放验证；未通过的接口明确记录，不能改变单主管要求。

**完成证据：** profile 加载、模型真实文字轮次与原生持久记录；区分实际调用与模拟验证。

**Spec 对照：** 用户故事 1、2、4、5、31、33、38、42；唯一主管、原生主会话、真实连接失败。
