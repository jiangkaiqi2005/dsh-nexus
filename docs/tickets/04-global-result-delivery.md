# 04：工作结果自动回到主管并继续推进

**要构建的行为：** 已有或新建工作会话结束一轮后，主管自动收到真实结果；闲时被唤醒，忙时随后处理，并自行决定汇报或下一步调度。

**阻塞于：** 03：让已有或新建工作会话执行任务。

**状态：** draft，待确认拆分方案；本轮不执行。

**范围与约束：** 覆盖全部工作会话终态，包含非 Nexus 创建的会话。模型决定动作与汇报时机，Host 不写死失败必插话、完成必汇报或修复审查循环。

- [ ] 工作轮次成功、失败和中断均能投递会话身份、相关轮次或消息身份、终态与实际最终内容。
- [ ] 主管空闲时被结果唤醒，真实模型作出有依据的回应或后续工具动作；不能只证明订阅到了事件。
- [ ] 主管正在处理用户输入时，结果保留并在后续处理机会进入模型；用户输入与结果均不丢失。
- [ ] 全局回流包含非直属、非 Nexus 创建的已有会话，不依赖用户手动搬运或主动查询。
- [ ] 重复、快照回放与实时事件交错不重复投递；不同会话与轮次不混淆，主管自身输出不会回流形成循环。
- [ ] 模型需要细节时可读取工作记录；不把全部历史、token 与工具日志无限复制到主管上下文。
- [ ] 主管根据目标与实际结果决定结束、追加任务、审查或报告阻塞；连接层不预设动作顺序和迭代次数。
- [ ] 真实 Host 演示空闲与忙时回流，并以可控事件补充去重、交错及失败边界验证。

**完成证据：** 工作终态、主管实际接收及后续处理的关联记录，区分接收与模型处理。

**Spec 对照：** 用户故事 15—22；空闲结果、忙时结果、结果身份。
