# 02：重启后恢复同一主管和原生记录

**要构建的行为：** 用户退出并重新启动 Harness 后，仍能进入原来的 Nexus 主会话，看到记录，并以相同 Realtime 型号继续交流；中断工作按原生语义收束，不被自动重跑。

**阻塞于：** 01：从原生侧栏与唯一 Realtime 主管文字交流。

**状态：** draft，待确认拆分方案；本轮不执行。

**范围与约束：** 使用原生持久化、独占写所有权及中断修补。保留默认工厂时，不能让通用冷恢复把主管恢复成默认工作 agent；插件自身识别主管身份并登记对应 driver。

- [ ] 正常退出后重启，主会话身份与原生记录保持，继续文字交流时仍只有一个 Realtime 主管。
- [ ] 恢复的模型上下文包含必要的既有交流；可通过新一轮回应验证，不只展示旧消息。
- [ ] 活动轮次中退出再启动，工具、步骤与轮次使用原生中断收束语义，无重复记录或盲目续跑。
- [ ] 插件初始化与用户进入主会话交错时，不误启默认工作 agent，不出现两个写入所有者或重复主管。
- [ ] 卸载、重新加载与有序退出释放主管、会话、连接及写所有权；再次进入仍可正常工作。
- [ ] 原生工作会话的新建和恢复行为保持正常；不通过替换全局 factory 解决主管恢复。
- [ ] 在实际退出与新进程重启边界验证持久记录和模型上下文；参考原生恢复测试补充可控中断检查。

**完成证据：** 重启前后会话身份、持久事件及继续交流的实际结果，无自动重跑记录。

**Spec 对照：** 用户故事 40、41；原生主会话、原生恢复与主管身份。
