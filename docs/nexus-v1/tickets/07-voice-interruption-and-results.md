# 07：语音打断时保留新输入与异步工作结果

**要构建的行为：** 用户在主管回复期间开口打断，停止旧语音并进入新一轮；同时到达的工作结果与工具响应仍被正确处理。

**阻塞于：** 06：实时通话期间持续调度工作会话。

**状态：** draft，待确认拆分方案；本轮不执行。

**范围与约束：** 处理音频与模型轮次打断，不据此自动取消工作会话任务。旧工具响应不能误接到新用户轮次，也不能为了续工具答丢弃新输入。

- [ ] 主管生成或播放语音时，用户开口可按模型原生轮次机制停止当前回复，清理待播放音频并接收新输入。
- [ ] 新用户轮次正常回应，原生记录与实际听到的语音状态一致，不把未交付片段伪装成完整回复。
- [ ] 用户新输入、工作终态与模型工具完成交错时，各自身份与顺序可追踪，没有结果丢失或错误回填。
- [ ] 被打断轮次的工具响应按实际协议处理；如果不能继续旧调用，保留任务事实并由主管后续处理，不静默忽略成功结果。
- [ ] 语音打断不会由 Host 强制取消工作会话；工作调整仍由主管理解用户新要求后决定。
- [ ] 延迟音频、旧响应或已结束轮次不在新轮次中继续播放；正常连续交流可恢复。
- [ ] 实际通话演示打断，并用可控延迟输入验证工具完成与异步结果的关键交错；分别标明真实与模拟证据。

**完成证据：** 可听见的打断效果、新用户轮次、异步结果及工具身份关联。

**Spec 对照：** 用户故事 27、28；正常通话与打断、忙时结果。
