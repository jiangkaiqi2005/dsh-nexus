# 05：用户途中修改要求后调整执行与主管安排

**要构建的行为：** Nexus 已派活后，用户在主管或工作会话中修改要求；相关 agent 接收原生引导，主管获知新要求，后续执行与安排以用户明确指令为准。

**阻塞于：** 04：工作结果自动回到主管并继续推进。

**状态：** draft，待确认拆分方案；本轮不执行。

**范围与约束：** 用户优先依靠来源与上下文表达，不增加指令版本仲裁、停止或补充意图分类，不按新输入自动强制取消。已经发生的副作用不作撤销承诺。

- [ ] 用户在主会话改变要求时，主管理解目标变化并向相关工作会话投递原生 steer 或按上下文安排后续行动。
- [ ] 用户直接在工作会话发出的引导同步给主管，保留真实用户来源，与 Nexus 调度和自动结果区分。
- [ ] 运行中工作 agent 在后续模型步骤读取新要求，实际后续行为反映新要求；主管结果与安排也反映变化。
- [ ] 主管忙时和闲时均能处理直接工作会话引导，不靠用户重复向两个地方输入。
- [ ] 在旧工作结果与新用户要求交错时，两者被保留，主管依据来源与上下文推进，不把旧结果当成新用户命令。
- [ ] 不引入自动取消或版本规则；用户需要停止时由 agent 理解要求并选择原生能力，不保证立即中断已启动工具。
- [ ] 真实演示一次执行中改要求及其最终结果；以可控输入覆盖忙时交错，验收观察行为而非只检查队列内容。

**完成证据：** 新要求的来源、原生引导进入步骤、修订后的工作结果及主管后续安排。

**Spec 对照：** 用户故事 12、23—26；来源与用户引导。
