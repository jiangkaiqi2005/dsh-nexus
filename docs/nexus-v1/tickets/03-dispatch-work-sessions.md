# 03：让已有或新建工作会话执行任务

**要构建的行为：** 用户在 Nexus 主会话用文字提出目标，主管读取全局会话、选择已有普通会话或创建工作会话，并通过真实工具调用让它开始执行。

**阻塞于：** 01：从原生侧栏与唯一 Realtime 主管文字交流。

**状态：** draft，待确认拆分方案；本轮不执行。

**范围与约束：** 调度覆盖全部工作会话，不依赖直属父子关系。工具走原生执行能力，主管默认委派具体工作；调度入口不成为 Nexus 的权限白名单。

**用户裁定（2026-10-09）：** Nexus 只管理、调度对话会话（普通会话）的 agent；会话 agent 产生的 subagent 会话 Nexus 不管。

- [ ] 主管可列出、读取全部工作会话的上下文与状态，包括用户创建、非直属子会话的已有普通会话。
- [ ] 实际 Realtime Function Calling 完成参数接收、原生工具执行、同一调用身份回填与主管文字续答，验证 text-only 工具联合链路。
- [ ] 用户指定一个已有会话时，任务进入该会话并由其原生 agent 执行；原有上下文和原生界面可用。
- [ ] 无适合会话时，主管可按目标创建工作会话，传递目标与工作区要求，实际启动工作。
- [ ] 主管可向运行中的会话投递原生引导，向闲置会话投递消息唤醒，并按模型决定使用原生停止能力。
- [ ] Nexus 调度与真实用户输入来源可区分，不经普通 prompt 入口冒充真实用户；无需逐会话同意、归属交接或 Nexus 审批。
- [ ] 验证主管具有 Spec 所要求的完整原生能力，不因只先演示调度工具而加入额外权限限制。
- [ ] 在真实 Host 中演示已有与新建会话执行；工具失败回填实际结果，不能把投递接受当成工作完成。

**完成证据：** 真实模型工具闭环、目标工作会话收到的来源与消息，以及实际工作记录；本票尚不要求自动结果回流。

**Spec 对照：** 用户故事 6—14、19；既有普通会话、来源、完整能力。
