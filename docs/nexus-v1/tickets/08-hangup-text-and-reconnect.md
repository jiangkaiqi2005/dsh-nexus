# 08：挂断后继续文字调度并可手动再接通

**要构建的行为：** 用户挂断时结束音频，主管和工作继续在同一主会话处理文字与工具；手动再次接通延续已有目标和上下文。

**阻塞于：** 06：实时通话期间持续调度工作会话。

**状态：** draft，待确认拆分方案；本轮不执行。

**范围与约束：** 同一个 Realtime 型号负责通话与挂断后的调度。只静音客户端不足以通过验收，必须停止后续音频生成；不结束主管或取消已派工作。

- [ ] 正常通话、正在生成语音及播放中均可挂断；停止采集与播放，清空待播放音频，处理在途模型响应。
- [ ] 挂断后的后续回应仅生成文字，实际协议证据中没有新的输出音频；旧迟到音频也不会被播放。
- [ ] 工作会话继续运行，结果回到主管，主管可实际执行 text-only 工具调用并续答。
- [ ] 文字输出与工具记录仍位于原来主会话，主管型号不变，不引入另一文字主管。
- [ ] 用户手动再接通时保留目标、必要交流及任务事实，能够继续通话而无需重新解释。
- [ ] 挂断、切换会话、刷新或重新挂载页面后保持文字模式，不自动再次采集音频。
- [ ] 在真实端点验证挂断后的文字工具联合链路；以可控延迟音频补充在途挂断及重复挂断检查。

**完成证据：** 挂断前后协议模态、采集和播放状态、同一主会话后续工具调度与手动接通。

**Spec 对照：** 用户故事 3、29—34、37；挂断文字闭环、在途挂断、手动再接通。
