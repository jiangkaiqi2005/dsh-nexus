# 10：断线或关闭客户端后保留主管工作

**要构建的行为：** 模型连接抖动或语音页面关闭时，工作事实仍保存；Host 继续文字工作，连接恢复后主管使用已有上下文，多个客户端不会形成重复音频链路。

**阻塞于：** 08：挂断后继续文字调度并可手动再接通。

**状态：** 已完成，2026-10-10 经用户实机验收后关闭。真实网络断线场景按用户决定不做实机测试，仅保留受控自动验证证据。

**范围与约束：** 不承诺永久云端 session。区分正在通话的网络恢复、主动挂断与页面刷新，后两种情况不能自动开麦。退出 Harness 本身仍走原生恢复语义。

- [x] Web 页面关闭但 Host 仍运行时，采集与播放结束，工作结果仍被主管处理并进入同一主会话文字记录。
- [x] 模型 WebSocket 断开时显示实际状态，保留已接收输入、任务结果和已完成工具事实；不能把断线当成工作完成。（受控自动验证通过；真实网络断线实机未测。）
- [x] 连接重建使用同型号与必要原生上下文，工具完成与结果不丢失、不重复执行；无法恢复的在途调用按真实状态处理。（受控自动验证通过；真实网络恢复实机未测。）
- [x] 通话中的传输恢复不改变用户已挂断或刷新后的文字状态，不绕过用户的麦克风选择。（受控自动验证通过；真实网络恢复实机未测。）
- [x] 两个页面或客户端进入同一主管时仅有一个音频采集与播放端；关闭旧客户端后仍可按手动操作接通。
- [x] Desktop 隐藏窗口、Web 页面关闭与退出 Harness 的状态正确区分；重启不自动续跑中断任务。
- [x] 实际客户端演示关闭后后台文字处理与重新进入，补充可控断线、迟到事件及未完成工具响应验证。

**完成证据：** 客户端关闭后的主管输出、重连上下文、工具与结果身份，以及单音频端状态。

实施、自动验证、诊断历史及最终用户验收见 [票 10 验证记录](../verification/10-disconnect-and-client-lifecycle.md)。用户确认第一页挂断后第二页可接通，并明确“现在全部通过了，10票收掉了，网络那个我不测”；关闭结论不代表真实网络断线实机已通过。

**Spec 对照：** 用户故事 28、34、38—41；客户端关闭、真实连接失败、恢复连续性。
